# Teams CSRC evaluation UI

Reusable local viewers for one `teams-csrc-gmeet-window-fixture-eval` result and its exact WAV
slice. Customer fixture data stays outside the repository.

## Generate a replay result

```bash
VEXA_STT_TOKEN=<token> pnpm exec tsx \
  /Users/dmitriygrankin/dev/vexa-csrc-virtual-channels/core/meetings/modules/mixed-pipeline/src/teams-csrc-fixture-eval.ts \
  --captured /absolute/private/fixture/captured-signal.jsonl \
  --csrc /absolute/private/fixture/csrc.jsonl \
  --wav /absolute/private/fixture/meeting.wav \
  --out /absolute/private/output/result.json \
  --slice-wav-out /absolute/private/output/audio.wav \
  --cache-dir /absolute/private/cache \
  --stt-url http://127.0.0.1:8085 \
  --start-sec 60 \
  --duration-sec 1200
```

The result includes the final candidate rows plus the ordered emission tape: draft, rewrite, clear,
timeout promotion, and final confirmation events with their virtual emission times.

## Run

```bash
node /Users/dmitriygrankin/dev/vexa-csrc-virtual-channels/core/meetings/modules/mixed-pipeline/eval-ui/server.mjs \
  --root /absolute/private/output \
  --port 8769
```

Audio-aligned diagnostic timeline:

```text
http://127.0.0.1:8769/?data=/result.json&audio=/audio.wav
```

Call-speed transcript replay through the shared transcript-rendering manager:

```text
http://127.0.0.1:8769/live.html?data=/result.json&audio=/audio.wav
```

The audio element is the replay clock. Seeking rebuilds transcript state through the same shared
draft/confirmed manager; playback releases only the events visible at that instant. The live view
shows first-visible and latest-update latency separately.

## Actual-pipeline wall-clock witness

The static emission-tape view above is useful for seeking, but it is not the delivery witness. For
the delivery witness, replay the captured inputs on wall clock into the actual
`TeamsCsrcGmeetPipeline`:

```bash
pnpm --filter @vexa/mixed-pipeline exec tsx \
  /Users/dmitriygrankin/dev/vexa-csrc-virtual-channels/core/meetings/modules/mixed-pipeline/src/teams-csrc-live-replay-server.ts \
  --captured /absolute/private/fixture/captured-signal.jsonl \
  --csrc /absolute/private/fixture/csrc.jsonl \
  --cache-dir /absolute/private/cache \
  --start-sec 60 \
  --duration-sec 1200 \
  --cadence-ms 2000 \
  --port 8771 \
  --stt-url http://127.0.0.1:8085 \
  --stt-model large-v3-turbo
```

`--stt-url` is optional. Without it, a content-addressed cache miss fails closed. With it, the
replay sends the exact corrected-cadence PCM slice through the normal `TranscriptionClient`, writes
the result into the private cache, and continues. Supply `VEXA_STT_TOKEN` in memory; never put a
token on the command line or in this repository.

Cadence boundaries are independent replay events, ordered after any PCM frame carrying the exact
same timestamp. Do not drive cadence from “the next audio frame”: captured PCM has multi-second
gaps, so an evaluator driven that way bunches overdue 2-second requests into sub-second bursts
while including future audio in earlier slices. Results generated by that ordering are not proof
for a candidate.

Then run the existing terminal interface with the same-origin development bridge enabled:

```bash
cd /Users/dmitriygrankin/dev/vexa-csrc-virtual-channels/clients/terminal
PORT=3003 \
VEXA_TEAMS_PIPELINE_BACKEND=http://127.0.0.1:8771 \
VEXA_TEAMS_PIPELINE_REFERENCE=/absolute/private/output/result.json \
node /Users/dmitriygrankin/dev/vexa-csrc-virtual-channels/clients/terminal/server.mjs
```

Open:

```text
http://127.0.0.1:3003/debug/teams-pipeline
```

This page mounts the terminal's actual `LiveTranscriptEngine`. It shows the measured two-second
pipeline cadence range separately from transcript-edge lag against synchronized audio. Speaker A/B labels are honest
unknowns until the existing corroborated Teams track namer earns a human name; when it does, stable
segment IDs repaint in place. The private fixture result is available only through the
development-only same-origin bridge and is not copied into the repository or exposed as a public
endpoint.

The shared buffer keeps the copied GMeet behavior by default. Teams enables two visibility-only
adaptations after the faithful window: a confirmed LocalAgreement prefix also publishes its
remaining Whisper segments as the pending tail, and a draft persisted by the four-second timeout
may continue to grow as `completed:true` when its words are a strict prefix of the new draft. Neither
path weakens confirmation of non-prefix revisions or the CSRC ownership gate.

Contested words are detected only from routed-CSRC overlap, matching contiguous text, and close
consensus word times. When both implicated rows have confirmed, both rows remain and the exact phrase
is wrapped as `⟦words⟧{CSRC A↔CSRC B}`. There is no speaker-owner heuristic, winner, loser, or row
deletion. The future session-local diarization design is documented in:

```text
/Users/dmitriygrankin/dev/vexa-csrc-virtual-channels/core/meetings/modules/mixed-pipeline/TEAMS_CSRC_CONTESTED_TRANSCRIPTS.md
```

The server binds only to `127.0.0.1`, serves fixture files only from the exact absolute `--root`,
rejects path escape, and supports HTTP byte ranges so playback and seeking work from any position.
