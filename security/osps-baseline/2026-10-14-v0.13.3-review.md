# OSPS Baseline — v0.13.3 review (2026-10-14)

A documentation review of what v0.13.3 changes against the OSPS Baseline controls that the
[2026-07-02 assessment](2026-07-02-assessment.yaml) passed. **The OSPS scanner was not re-run for
this review.** The scanner reads the repository through the GitHub API with a token, so its run
belongs to the release workflow or a maintainer, after the release branch is public. Until that
run is committed here, the 2026-07-02 result is the latest scanner evidence, and it predates every
0.13 change.

## What changed since the last scan

| Area | Change in 0.13 (to v0.13.3) | Controls it touches |
|---|---|---|
| Access control inside the product | Turns read by other people run with a shared scope and no person-wide reads; the session store has its own database role and a bucket-scoped key; event agents run with least privilege; the worker harness environment withholds the worker's own credentials; model catalog entries can be limited to named people; workspace access follows membership; a connection setting is saved only by the person's own client; instance flows are writable only by the admin account; cross-person agent messages are off by default. | OSPS-AC (product-level; the scanner checks repository settings, not these) |
| Secrets in deployment | No published default secrets: admin token, database and Redis passwords, sign-in and dispatch signing keys must be minted, and services refuse to boot on a published value. | OSPS-BR, OSPS-DO (deployment docs) |
| Unproven features | Built-but-unproven features ship behind switches that are off by default (`VEXA_FEATURES`). | OSPS-DO (release notes, upgrade guide) |
| Release artifacts | Service images are renamed `vexaai/vexa-<service>`; v0.13.3 also pushes the `v012-` names with the same digest. Digests are pinned when images are promoted. | OSPS-BR (build and release) |
| Runtime hardening | Services run as uid 10001; Helm networks are default-deny; private-address webhooks and endpoints are refused. | OSPS-AC, OSPS-VM (exposure) |
| Contributions | DCO sign-off on every commit since v0.13.1; a contribution-rights check on pull requests. | OSPS-LE (legal), OSPS-GV (governance) |

|---|---|---|

| npm dependencies (`pnpm audit`, 2026-10-14) | Yes | 1 moderate, 1 low: exactly the two advisories accepted in [known-advisories.md](../known-advisories.md). No high or critical. |

| Dependency licenses | Yes | `gate:licenses` and `gate:image-licenses` green; exceptions are the logged ones in `license-exceptions.json`. |
| DCO | Yes | Every commit since v0.13.1 is signed off. Not every commit on the 0.13 line before v0.13.1 is. |
