- **Added (API):** a denied call now tells you how to fix it. Every `401` from the gateway carries `WWW-Authenticate: Bearer`, so a client learns which scheme to retry under instead of guessing between a bearer token, an api-key header and a login flow. Every scope `403` now carries **`required`** (what the route accepts) and **`granted`** (what the presented key actually holds) as fields beside `detail`, plus a one-line remediation. The pair was already computed and logged; it was dropped before it reached the caller, so an under-scoped client was told it lacked *something* and never what. `detail` is unchanged.
- **Added (MCP):** an **`auth_me`** tool (11 tools now) wrapping `GET /auth/me` — `user_id`, `email`, `scopes`, `max_concurrent`. It is the authoritative answer to what a key may do: a key's `vxa_<scope>_` prefix is a naming hint recorded at mint time, and the scopes column on the key record is what the gateway enforces.
- **Added (MCP):** a **`vexa.capabilities`** prompt (5 prompts now) — the orientation an agent reads before its first call: the base URL, `VEXA_API_KEY`, the three scopes (`bot`, `tx`, `browser`) and what each grants, and what to do on a 401, a 403 or a 503.
- **Fixed (MCP):** the meeting-prep prompt and the service README no longer claim that storing notes on a meeting record is unavailable — those `PATCH` routes shipped.
