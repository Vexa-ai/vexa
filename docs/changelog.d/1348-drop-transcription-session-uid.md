- **`transcriptions.session_uid` is gone: nothing read it (#1348).** The column was `NULL` on every row a bot captured and held a derived `import-<source>-<meeting_id>` on imported rows, and no endpoint, serializer or client ever returned it. The collector no longer writes it and the model no longer defines it, so a fresh install has no such column. An existing database keeps it until you drop it (schema convergence never drops): run `MIGRATION-0017-drop-transcription-session-uid.md` after every meeting-api of the previous release is gone. Only readers of your own that select `transcriptions.session_uid` are affected. `meeting_sessions.session_uid`, the bot's connection id, is unchanged. `transcript.v1`'s `SessionStart` and `Transcription` envelopes no longer require a `session_uid` the bot never sent; `SessionEnd` and the per-meeting feed entries still carry it.
