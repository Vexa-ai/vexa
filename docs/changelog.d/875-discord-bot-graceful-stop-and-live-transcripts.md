- **Fixed (Discord):** the Discord platform-lane bot can now be gracefully stopped. meeting-api's real leave command carries a `meeting_id` field the sealed acts.v1 `Leave` schema forbids, so the bot's strict schema validation was silently dropping every real `DELETE /bots/discord/{id}` and only meeting-api's hard-kill reconcile ever tore the bot down. `parse_act` is now structurally lenient (checks that `action` is a known acts.v1 verb, matching the TS reference adapter), so the real leave command is honored and the bot emits its `completed` lifecycle event and disconnects on request (#875).
- **Fixed (Discord):** live Discord transcripts now render immediately instead of only after a page reload. Segments were published without `absolute_start_time` / `absolute_end_time`, and the live pub/sub ingestion path has no backfill for those fields (only the REST read path backfills them), so the shared renderer dropped every segment until the next reload hit REST. The bot now stamps both fields at emission time, mirroring the TS reference bot's producer chokepoint (#875).
