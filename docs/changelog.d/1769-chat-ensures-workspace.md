- **Agent: the first chat from a new user no longer fails before the worker starts.** On a Compose stack, `POST /agent/chat` for a user with no workspace yet returned an opaque `500`, because the worker's workspace folder did not exist when Docker started it. agent-api now provisions the user's workspace (the same idempotent step `POST /agent/workspace/init` runs) before it spawns the worker. A concurrent first chat and init for the same user provision once, a provisioning failure returns a `503` instead of a `500`, and an invalid user id returns `400`.
