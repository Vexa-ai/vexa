- **Claude Code plugin 0.2: no API key, and a meeting pane.** The `vexa` plugin now connects to hosted Vexa (`https://api.cloud.vexa.ai/mcp`) and signs in with OAuth, so installing it asks for nothing. It opens a Vexa pane beside the chat that shows the sign-in step, then a meeting-link field, **Send bot**, **Try a demo** and the live transcript. The pane's own calls and Vexa's read-only tools run without a prompt; `speak_in_meeting`, `stop_bot` and other meeting actions the model takes still ask. Self-hosted stacks add the server with `claude mcp add` and their key.
- **Claude Code plugin: a listener for live calls.** When one of your meetings is live, a band above the prompt offers to listen. After you press **Listen**, each change in that meeting's transcript goes to a small model with plain-language listen rules (kept in the signals.v1 brief shape the app's meeting listener uses), and Claude gets a turn with the excerpt when something matters. `listener_calibrate` replays a labelled fixture through it and reports precision, recall and latency. Claude tunes the brief per conversation (presets for sales, standups and interviews) with the `listener_configure` tool, which can change or stop the listener but never start it. The pane shows what it listens for and each time it woke Claude.
- **The plugin's pane and listener run from an app folder.** The plugin ships Vexa's default app (`clients/claude-plugin/app`): a `vexa-app.json` manifest (`schema` `vexa-app/v1`, `name`, `version`, `upstream`, `entry`), the pane's copy in `pane.json`, and one listen brief per kind of conversation under `listener/`. On first run it is copied to `~/.vexa/apps/meeting-assistant/`; a plugin update merges into that copy without overwriting edited files (the new version lands beside them as `.upstream`), and `/vexa-app-reset` restores the shipped version with a backup. A project's own `.vexa/app/` wins over both; `/vexa-app-seed` copies the app there to commit.
- **Plugin setup happens in the chat.** Before sign-in the Vexa pane shows one status line; Claude, told by a short session-start context what is connected, asks the next question in chat and saves the answer with the plugin's `vexa_settings` tool: where it keeps what it learns (a cloud workspace — also the account's «Writes to …» default — this computer, or only when asked). When writing is allowed, a finished call is filed into that workspace by the workspace's own `CLAUDE.md` rules (new `vexa-workspace` skill), with one line and a link back in chat.
