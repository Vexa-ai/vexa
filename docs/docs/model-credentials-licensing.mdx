Vexa agent workers run the official `claude` CLI (interactive turns via the harness, one-shot
completions via `claude -p`). The credential that powers them is chosen per deployment and per
user (**Settings → Models**, resolved user > global > deployment env). Which credential you pick
determines **which Anthropic terms you operate under**.

## How Vexa's credential modes map

**Subscription mode** ("Claude subscription (deployment credentials)"):

- Workers invoke the **official `claude` binary** — never the raw HTTP API with an OAuth token.
  The credential file (`~/.claude/.credentials.json`) is bind-mounted read-only into worker
  containers at the CLI's own standard path; only the official client consumes it. The token is
  never extracted into headers, third-party clients, or proxies.
- `claude -p` completions are plain subprocess calls of the compiled CLI. Per the Agent SDK help
  article, third-party apps authenticating with your subscription through the Agent SDK are a
  **covered, credit-metered use**: programmatic usage draws a per-user monthly **Agent SDK
  credit** (plan-dependent; overage at API rates when enabled). Nothing simulates a terminal to
  disguise programmatic calls as interactive use.

**Custom mode** (API key / OpenAI-compatible gateway):

- Raw-API auth (`ANTHROPIC_BASE_URL`/`ANTHROPIC_AUTH_TOKEN`) is only ever used when the
  deployment or user supplied an **API key** —
  Commercial Terms, no consumer authentication restrictions.
- An API key never reaches a worker. agent-api seals it into the turn's route for the **model
  proxy**, and the worker presents a per-turn token there instead
  ([Execution](/architecture/execution#the-model-proxy)). A
  subscription is never moved into that proxy: it stays with the official CLI, as above.
- A user's own endpoint must pass the operator's allow-list, `VEXA_MODEL_BASE_URL_ALLOW`. Unset, it
  admits the deployment's own gateway plus `api.anthropic.com` and `openrouter.ai`. A private
  inference server must be named in it explicitly (see [Configuration](/configuration)).
- A user's own endpoint carries only that user's own key, an empty one included. The deployment's
  key and mounted subscription never ride to it.

## The boundary: one human, one subscription, one beneficiary

<Warning>
A consumer subscription is a personal license. The moment a deployment serves **other users'
turns** on the operator's Pro/Max credential, it becomes "routing requests through plan
credentials on behalf of their users" — the explicitly disallowed case.
</Warning>

- **Self-host, single user** — your machine, your subscription, your turns: subscription mode as
  the deployment default is ordinary individual use.
- **Any multi-user or hosted deployment** — the deployment default must be an **API key**
  (Settings → Models → Custom endpoint, or `ANTHROPIC_API_KEY` in the deployment env), or each
  user brings their own credential via user-level settings. Never default tenants onto anyone's
  consumer OAuth.

## Operator checklist

1. Exactly **one human** benefits from a mounted subscription credential. If
   `HOST_CLAUDE_CREDENTIALS` is set and more than one active user runs turns, switch the
   deployment default to an API key.
2. Never move the OAuth token out of the credentials file — no proxies, no header injection, no
   gateway re-serving. API-style env vars are for API keys only.
3. Expect `claude -p` usage to draw the Agent SDK credit separately from interactive limits —
   exhaustion is a billing event, not a bug (it surfaces as a model-inference failure in the
   worker).
4. When in doubt for a new topology: **use an API key** — the Commercial Terms path has no
   authentication-shape restrictions.

## How it works

1. **Resolve.** For each turn, agent-api takes the user's effective **Settings → Models** config
   (user, then global, as admin-api resolves it). The deployment env fills anything unset.
2. **Subscription mode.** Only the model names apply. The worker runs on the deployment's
   credential: the `HOST_CLAUDE_CREDENTIALS` file, bind-mounted read-only at the CLI's own path, or
   `ANTHROPIC_API_KEY`.
3. **Custom mode.** The endpoint host must match `VEXA_MODEL_BASE_URL_ALLOW` (or its default). A
   loopback, private or single-label host matches only an exact entry. A `claude-code` turn also
   needs the user's own key.
4. **Refused.** A refused endpoint is not used: the refusal is logged and filed as a friction
   record naming the key to change.
5. **Admitted.** The dispatch seals the user's endpoint and key into the turn's route for the model
   proxy, and stamps the proxy and the turn's token under the names each harness reads. On that
   route the CLI starts with no stored subscription credential beside it.
6. **Subscription route.** With no API key on the route, the deployment's subscription applies: the
   dispatch stamps `CLAUDE_CODE_OAUTH_TOKEN` (or the runtime mounts the credentials file) for the
   CLI itself, every API-key name stays empty, and the CLI calls Anthropic directly.

## Why it complies

| Rule | How this design meets it | Enforced by |
|---|---|---|
| P14: config is a validated contract | `VEXA_MODEL_BASE_URL_ALLOW` and `HOST_CLAUDE_CREDENTIALS` are declared in `config.v1.json` with their defaults | `gate:config-contract` |
| P23 and ADR-0044: no duplicated fact drifts | The endpoint gate reads addresses through the shared `ssrf.py`, a byte-identical copy of `outbound-url.v1` | `gate:fact-parity` (fact `outbound-url-guard`) |
| P18: fail loud | A refused endpoint is logged and filed as friction; the Test button refuses what the dispatch refuses | ungated: reviewed; tests below |

**Security.** No worker holds an API key — deployment, catalog or the user's own (H5/W1). Deny
tests: `core/agent/tests/test_model_proxy.py` (`test_no_key_appears_in_the_worker_env_or_its_delivered_turn`,
`test_a_token_from_another_turn_is_refused`, `test_an_expired_token_is_refused`,
`test_a_model_outside_the_turns_scope_is_refused`,
`test_a_subscription_route_keeps_its_credential_with_the_cli_and_is_never_proxied`) and
`core/agent/tests/test_sec_deny_policy_taint.py` (`test_model_shell_holds_no_provider_key`).

A user's endpoint is an outbound destination a non-operator chose, so it is
default-deny. Deny tests: `core/agent/tests/test_model_endpoint.py`
(`test_a_custom_endpoint_never_inherits_the_deployment_token`, `test_a_non_allowlisted_endpoint_is_refused`,
`test_a_wildcard_never_reaches_the_deployments_own_network`, `test_no_private_address_is_a_product_default`)
and `core/agent/tests/test_own_endpoint_credentials.py`
(`test_on_the_persons_route_the_cli_starts_with_no_stored_credential`,
`test_a_keyless_own_endpoint_on_claude_code_is_refused`).
