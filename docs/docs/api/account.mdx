---
title: "Account settings API"
description: "Per-user model and transcription configuration — read and write your own account's overrides."
---

Two self-serve settings pairs let a key holder configure their own account: which model credential
Vexa uses for that user, and which transcription backend their bots send audio to. Both override the
deployment default for that user only.

Same base URL and auth as the rest of the API
([base URL & auth](/api/meetings#base-url--auth)). Related settings live on their own pages:
[Webhooks](/webhooks) and the [Calendar API](/api/calendar).

Both `PUT`s are **partial**: only the fields you send change, and an empty string clears a field.
Both return the same shape their `GET` returns, with secrets masked to their last four characters.

## Models

```bash GET /user/models
curl -H "X-API-Key: $API_KEY" "$API_BASE/user/models"
```

```json Response
{ "mode": "custom",
  "model": "claude-sonnet-4-5",
  "meeting_model": null,
  "base_url": "https://api.anthropic.com",
  "api_key_set": true,
  "api_key": "********a91f" }
```

```bash PUT /user/models
curl -X PUT "$API_BASE/user/models" \
  -H "X-API-Key: $API_KEY" -H "Content-Type: application/json" \
  -d '{"mode":"custom","base_url":"https://api.anthropic.com","api_key":"<key>"}'
```

<ParamField body="mode" type="string">`subscription` or `custom`. Any other value is `422`.</ParamField>
<ParamField body="model" type="string">Model id for general work.</ParamField>
<ParamField body="meeting_model" type="string">Model id for meeting work, when it should differ.</ParamField>
<ParamField body="base_url" type="string">An `http(s)` URL for an OpenAI-compatible or Anthropic-compatible endpoint. Anything else is `422`.</ParamField>
<ParamField body="api_key" type="string">Credential for that endpoint. Stored, never echoed in the clear.</ParamField>

Which mode your deployment may use is a licensing question, not just a configuration one — read
[Model credentials & licensing](/model-credentials-licensing) before pointing a multi-user
deployment at a subscription credential.

## Transcription

Override the STT backend for this user's bots. The deployment-wide equivalents are
`TRANSCRIPTION_SERVICE_URL` / `TRANSCRIPTION_SERVICE_TOKEN` — see
[Bring your own STT](/how-to/custom-stt).

```bash GET /user/transcription
curl -H "X-API-Key: $API_KEY" "$API_BASE/user/transcription"
```

```json Response
{ "url": "https://stt.example.com", "token_set": true, "token": "********c4d2" }
```

```bash PUT /user/transcription
curl -X PUT "$API_BASE/user/transcription" \
  -H "X-API-Key: $API_KEY" -H "Content-Type: application/json" \
  -d '{"url":"https://stt.example.com","token":"<token>"}'
```

<ParamField body="url" type="string">Base URL of an OpenAI-compatible transcription endpoint. Vexa appends `/v1/audio/transcriptions`. Non-`http(s)` values are `422`.</ParamField>
<ParamField body="token" type="string">Bearer token for that endpoint, if it requires one. Stored, never echoed in the clear.</ParamField>

Resolution is field by field: a value set here wins over the platform setting, which wins over the
deployment environment. A user with no transcription override uses the deployment's backend.

Every field on both routes is capped at 2,048 characters; longer values are `422`.
